## The problem: messy tables break distance-based models

In the last lesson, k-nearest neighbours fell apart twice: first when one column was measured in euros and another in years, and again when we added irrelevant noise columns. Real business tables look like that *every day* — mixed units, skewed distributions, dozens of useless columns, and non-linear threshold rules ("flag if temperature > 5.5°C AND RPM > 4,200").

Enter the undisputed workhorse of tabular machine learning: **<Term id="decision-tree">decision trees</Term>** — and the two ensemble families built out of them, **<Term id="random-forest">Random Forests</Term>** and **<Term id="gradient-boosting">Gradient Boosted Trees</Term>** (XGBoost, LightGBM, CatBoost).

A decision tree plays Twenty Questions. At each node it asks one axis-aligned yes/no question ("is $x_1 \le 5.19$?"), splits the rows into a left bucket and a right bucket, and repeats until the buckets are pure or a depth limit stops it. Notice two superpowers that fall out for free:

- **Scale invariance:** multiply a column by 1,000, and every threshold simply multiplies by 1,000. The splits and predictions are identical to the last decimal place.
- **Built-in feature selection:** if a column is pure random noise, splitting on it barely improves bucket purity, so the greedy search skips it.

## Choosing the best question: Gini impurity

How does the tree decide *which* feature and threshold to split on? It measures how mixed each bucket is using **<Term id="gini-impurity">Gini impurity</Term>** — the probability that two points picked at random from the bucket have different labels:

<Eq
  words="\cc{\text{Gini impurity}} = 2 \times \ca{\text{share of class } 1} \times (1 - \ca{\text{share of class } 1}), \qquad \cp{\text{gain}} = G_{\text{parent}} - \Big(\frac{n_L}{n} G_L + \frac{n_R}{n} G_R\Big)"
  tex="\cc{G} = 2\,\ca{p}(1 - \ca{p}), \qquad \cp{\Delta G} = G_{\text{parent}} - \left(\frac{n_L}{n} G_L + \frac{n_R}{n} G_R\right)"
>

- $\ca{p}$ — fraction of class-1 examples in a bucket ($0$ or $1$ gives $G = 0$, completely pure; $0.5$ gives $G = 0.5$, maximally mixed)
- $n_L, n_R$ — number of rows sent to the left and right child buckets ($n_L + n_R = n$)
- $\cp{\Delta G}$ — **impurity reduction (gain)**: the greedy CART algorithm scans every candidate threshold on every feature and picks the split with the largest $\Delta G$

</Eq>

## One deep tree memorises — a Random Forest averages the variance away

Greedy trees have one glaring flaw: **high variance**. Let a single tree grow to depth 10 on noisy data, and it will happily carve tiny custom boxes around every single mislabelled training point! Worse, change 5% of the training rows and the very first root split can flip, changing the entire tree underneath it.

That trick — **B**ootstrap **AGG**regat**ING** (**bagging**) plus random feature subsets at every split — is a **Random Forest**. In bias–variance language from Module 7: each deep tree has low bias and huge variance; averaging $B$ decorrelated trees leaves the bias untouched while slashing variance!

## Gradient Boosted Trees: fixing mistakes sequentially

Random Forests build many deep trees **in parallel** to cancel variance. **Gradient Boosted Trees (GBT)** take the opposite strategy: start with a tiny, high-bias tree (depth 1–3) and add new shallow trees **one by one**, where each new tree predicts the **residuals** (errors) left behind by the ensemble so far:

<Eq
  words="\cc{\text{new score}} = \ca{\text{previous score}} + \cp{\eta} \times \cb{\text{small tree fitted to remaining errors}}"
  tex="\cc{F_m(\mathbf{x})} = \ca{F_{m-1}(\mathbf{x})} + \cp{\eta}\,\cb{h_m(\mathbf{x})}, \qquad r_i = y_i - \sigma\!\big(\ca{F_{m-1}(\mathbf{x}_i)}\big)"
>

- $\ca{F_{m-1}(\mathbf{x})}$ — the ensemble's log-odds prediction after $m - 1$ rounds
- $r_i = y_i - \sigma(F_{m-1}(\mathbf{x}_i))$ — the **residual** (negative gradient of log-loss) on example $i$: large where the current ensemble is still wrong, near zero where it is already confident and right
- $\cb{h_m(\mathbf{x})}$ — a fresh shallow regression tree fitted to those residuals (XGBoost and LightGBM compute exact second-order Newton leaf weights $\gamma = \sum r_i / (\sum p_i(1-p_i) + \lambda)$)
- $\cp{\eta}$ — the shrinkage **learning rate** (e.g. 0.05–0.3) that keeps each tree from over-correcting

</Eq>

Look at two honest findings in the numbers above:
1. **Trees crush kNN on messy tables with zero preprocessing:** raw kNN scores **70.0%** (destroyed by the 1,000× scale mismatch), scaled kNN improves to **81.2%** (still dragged down by 6 noise columns), while a single tree hits **91.2%**, Random Forest hits **91.9%**, and depth-2 GBT hits **93.1%** at round 5!
2. **Bagging resists overfitting; boosting *can* overfit.** Watch GBT's test accuracy as you step past round 5: it peaks at **93.1%** (round 5) and drifts down to **89.2%** by round 30 as training accuracy climbs! Once the true rule is learned, the only large residuals left are the 6% flipped training labels — so later boosting rounds start memorising label noise. That's why real GBT workflows rely on small learning rates, shallow trees, and **early stopping** on a validation set.

<Misconception>

"Random Forests and Gradient Boosted Trees never overfit as you add more trees." Random Forests (bagging) are remarkably resistant to adding more trees because averaging independent noisy predictors only shrinks variance. **Gradient Boosting is different:** each new tree actively fits the remaining training residuals, so running too many boosting rounds on noisy data *will* overfit! Always watch a validation curve to pick the number of boosting rounds.

</Misconception>

## In code

Finding the exact greedy Gini split — and verifying its 100% invariance to a 1,000× column rescaling — takes twenty-five lines of NumPy:

```python
import numpy as np

def gini(y):
    if len(y) == 0:
        return 0.0
    p = np.mean(y == 1)
    return 2.0 * p * (1.0 - p)

def best_split(X, y):
    n, d = X.shape
    parent = gini(y)
    best = (0.0, None, None)  # (gain, feature, threshold)
    for f in range(d):
        vals = np.unique(X[:, f])
        for t in (vals[:-1] + vals[1:]) / 2:
            left = y[X[:, f] <= t]
            right = y[X[:, f] > t]
            weighted = (len(left) * gini(left) + len(right) * gini(right)) / n
            gain = parent - weighted
            if gain > best[0]:
                best = (gain, f, float(t))
    return best

rng = np.random.default_rng(19)
X = rng.uniform(0, 10, size=(60, 2))
y = ((X[:, 0] > 5.0) & (X[:, 1] > 3.5)).astype(int)

gain, feat, thresh = best_split(X, y)
print(f"Best greedy split: x{feat+1} <= {thresh:.2f} (Gini gain = {gain:.3f})")

# Multiply feature 2 by 1,000: identical gain, scaled threshold!
X_scaled = X.copy()
X_scaled[:, 1] *= 1000
gain2, feat2, thresh2 = best_split(X_scaled, y)
print(f"After 1000x rescale: x{feat2+1} <= {thresh2:.2f} (Gini gain = {gain2:.3f})")
```

<Takeaways>

- **Decision trees** partition feature space with axis-aligned splits chosen greedily by **Gini impurity reduction** (or entropy gain). They are **100% invariant to monotone feature scaling** and naturally skip irrelevant columns.
- **Single deep trees overfit** (high variance — 99.3% train / 84.8% test on noisy data).
- **Random Forests (bagging)** average many bootstrap trees built with random feature subsets, slashing variance and shrugging off heavy label noise — though heavy feature subsampling can get diluted when most columns are pure noise.
- **Gradient Boosted Trees (boosting)** add shallow trees sequentially to fit remaining residuals (reducing bias). They dominate structured tabular benchmarks, *provided* you control depth, shrinkage and early stopping so they don't chase label noise.

</Takeaways>

<InTheWild>

On structured tabular datasets (credit risk, fraud detection, ad click prediction, churn, demand forecasting, Kaggle tabular competitions), **Gradient Boosted Decision Trees** — specifically **XGBoost**, **LightGBM** and **CatBoost** — routinely match or beat deep neural networks while training 100× faster and handling missing values, mixed numeric scales and uninformative columns out of the box. Neural networks win on perceptual and sequential modalities (images, audio, text); tree ensembles still rule spreadsheets and SQL tables.

</InTheWild>
