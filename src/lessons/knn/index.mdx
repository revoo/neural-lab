## The problem: what if there is no training at all?

Every classifier we've met so far — neurons, MLPs, logistic regression — spends effort during training compressing the dataset into a handful of weights $\mathbf{w}$, and then throws the raw training points away.

What if you refuse to compress anything? Store the training dataset verbatim. When a new point $\mathbf{x}$ arrives, measure its distance to every stored example, find the **$k$ closest neighbours**, and let them vote.

That algorithm is **<Term id="knn">k-nearest neighbours</Term>** (kNN). Training time is literally **zero** (it just remembers the data — which is why it's called a **lazy**, non-parametric learner). And because it makes no assumption that the boundary is a straight line or a circle, it can trace arbitrarily twisted shapes out of the box.

Of course, there is no free lunch: because kNN relies 100% on distances, *anything* that corrupts distance breaks kNN immediately. Let's watch both its magic and its two fatal traps in action.

## Distance, voting, and the bias–variance dial $k$

First, how do we measure "closest"? Usually straight-line **Euclidean ($L_2$)** distance, or grid-style **Manhattan ($L_1$)** distance:

<Eq
  words="\cc{\text{Euclidean distance}} = \sqrt{\sum_{j=1}^{d} (\ca{x_j} - \cb{x'_j})^2}, \qquad \cp{\text{Manhattan distance}} = \sum_{j=1}^{d} |\ca{x_j} - \cb{x'_j}|"
  tex="\cc{d_2(\ca{\mathbf{x}}, \cb{\mathbf{x}'})} = \sqrt{\sum_{j=1}^{d} (\ca{x_j} - \cb{x'_j})^2}, \qquad \cp{d_1(\ca{\mathbf{x}}, \cb{\mathbf{x}'})} = \sum_{j=1}^{d} |\ca{x_j} - \cb{x'_j}|"
>

- $\ca{\mathbf{x}}$ — the new **query** point you want to classify
- $\cb{\mathbf{x}'}$ — a stored **training** point
- $d$ — the number of input features
- $\cc{d_2}$ — straight-line distance (circles of equal distance)
- $\cp{d_1}$ — city-block distance (diamonds of equal distance)

</Eq>

Once you have the $k$ nearest training points, they either cast equal votes (**uniform** voting) or closer neighbours get a louder voice (**distance weighting**, $w_i = 1 / (d_i + \varepsilon)$).

## Trap 1: The feature scaling disaster

Now imagine a real loan dataset with just two columns: **Age** (20–70 years, SD ≈ 12) and **Annual Income** (€20,000–€120,000, SD ≈ €24,000). Both features strongly drive approval (Age actually carries slightly *more* signal than Income).

A 30-year age difference contributes $30^2 = 900$ to squared Euclidean distance. A €1,000 income difference contributes $1{,}000^2 = 1{,}000{,}000$ — **over a thousand times larger**! Age effectively disappears from the distance formula, collapsing test accuracy from **93.0%** down to **62.0%**.

</Predict>

The fix is **<Term id="feature-scaling">feature scaling</Term>** (z-score standardisation): subtract each column's training mean and divide by its training standard deviation, so every feature has mean 0 and SD 1:

<Eq
  words="\cc{\text{scaled feature}} = \frac{\ca{\text{raw value}} - \cb{\text{training mean}}}{\cp{\text{training SD}}}"
  tex="\cc{z_j} = \frac{\ca{x_j} - \cb{\mu_j}}{\cp{\sigma_j}}"
>

- $\ca{x_j}$ — raw value of feature $j$
- $\cb{\mu_j}, \cp{\sigma_j}$ — mean and standard deviation of feature $j$, **computed on the training set only** (using test-set statistics would leak test information into preprocessing)
- $\cc{z_j}$ — dimensionless z-score measuring how many standard deviations away from average the value sits

</Eq>

## Trap 2: The curse of dimensionality

Even after you scale every column to SD 1, kNN has a second Achilles' heel that connects straight back to Module 1's *High-Dimensional Geometry*.

Unlike logistic regression (which can learn weight $w_j \approx 0$ for an irrelevant column) or decision trees (which simply never split on useless columns), plain kNN gives **every single column equal weight 1** inside $\sum_{j=1}^d (x_j - x'_j)^2$. Add irrelevant random noise columns, and their squared differences pile up until every training point sits at almost the same distance from your query.

Watch a real `k = 5` kNN classifier on a clean 2D ring get buried alive as we append 0 to 80 pure random noise columns:

<NoiseDimsWidget />

- At **0 noise columns (2D):** farthest/nearest ratio is **30.13×**; kNN hits **96.0%**.
- At **5 noise columns (7D):** farthest/nearest drops to **4.05×** and accuracy already plunges to **67.5%**.
- At **80 noise columns (82D):** farthest/nearest shrinks to **1.43×** — every neighbour is essentially a random draw from the dataset, and test accuracy collapses to **46.0%** (worse than flipping a coin!).

<Misconception>

"kNN is fast because training takes zero seconds." Training is $O(1)$, which makes *prediction* the bottleneck: a naive query computes distances to all $N$ stored training points ($O(N d)$ per query) and has to hold the entire training set in RAM. On 10 million vectors, brute-force kNN is far too slow for real-time serving — which is why production vector databases use approximate nearest-neighbour indexes like **HNSW** or **IVF** (and why low-dimensional learned embeddings matter so much).

</Misconception>

## In code

A complete kNN classifier with leakage-free train-only standardisation takes twenty lines of NumPy:

```python
import numpy as np

def knn_predict(X_train, y_train, X_test, k=5, weighted=False):
    preds = []
    for q in X_test:
        dists = np.linalg.norm(X_train - q, axis=1)
        idx = np.argsort(dists)[:k]
        w = 1.0 / (dists[idx] + 1e-6) if weighted else np.ones(k)
        score = np.sum(w * (y_train[idx] == 1)) / np.sum(w)
        preds.append(int(score >= 0.5))
    return np.array(preds)

# Age (20-70) vs Annual Income (20k-120k): fit scaler on train ONLY!
rng = np.random.default_rng(42)
z_tr = rng.normal(size=(120, 2))
z_te = rng.normal(size=(200, 2))
y_tr = (1.6 * z_tr[:, 0] + z_tr[:, 1] + 0.45 * rng.normal(size=120) > 0.1).astype(int)
y_te = (1.6 * z_te[:, 0] + z_te[:, 1] + 0.45 * rng.normal(size=200) > 0.1).astype(int)

X_tr_raw = np.column_stack([44 + 12 * z_tr[:, 0], 65000 + 24000 * z_tr[:, 1]])
X_te_raw = np.column_stack([44 + 12 * z_te[:, 0], 65000 + 24000 * z_te[:, 1]])

mu, sd = X_tr_raw.mean(axis=0), X_tr_raw.std(axis=0)
X_tr_sc, X_te_sc = (X_tr_raw - mu) / sd, (X_te_raw - mu) / sd

print(f"Raw k=5 accuracy:          {100 * (knn_predict(X_tr_raw, y_tr, X_te_raw, 5) == y_te).mean():.1f}%")
print(f"Standardised k=5 accuracy: {100 * (knn_predict(X_tr_sc, y_tr, X_te_sc, 5) == y_te).mean():.1f}%")
```

Running it prints:

```text
Raw k=5 accuracy:          70.0%
Standardised k=5 accuracy: 89.5%
```

<ForReal>

Every bug in this lab shows up in real nearest-neighbour pipelines: forgetting a `StandardScaler` inside a `scikit-learn` pipeline before Euclidean distance lets a millisecond timestamp drown out every other feature; concatenating unvetted metadata columns into a search vector triggers the curse of dimensionality; and uniform top-$k$ voting in anomaly detection or recommendation erases niche clusters unless you weight by similarity (`1/d` or softmax temperature). Modern embedding search (FAISS, HNSW, pgvector) solves the scaling and noise problems upstream by letting a neural encoder learn a unit-norm metric space first.

</ForReal>

<Takeaways>

- **kNN is a lazy, non-parametric learner:** zero training cost, flexible local boundaries, $O(N d)$ query cost unless accelerated with an index.
- **$k$ is the bias–variance knob:** small $k$ ($k = 1$) memorises every outlier (100% train, jagged islands); large $k$ over-smooths curves and erases small minority pockets. Distance weighting ($1/d$) preserves local pockets even at moderate $k$.
- **Always scale features before measuring distance** (fit mean/SD on the training set only). Otherwise wide-range units like euros completely drown out narrow-range units like years.
- **Irrelevant columns kill kNN** via the curse of dimensionality: because every feature enters distance with weight 1, noise columns flatten `farthest / nearest` toward 1 and collapse neighbourhoods.

</Takeaways>

<InTheWild>

While raw tabular kNN struggles on wide noisy tables, **nearest-neighbour search in learned embedding spaces** is one of the most heavily used primitives in modern AI! Every RAG vector database (pgvector, Qdrant, Pinecone, FAISS, ScaNN), image reverse-search engine, music/product recommender, and face-recognition matcher is running kNN (or approximate kNN via HNSW graphs) over dense vectors where a neural network has already handled feature scaling and thrown away irrelevant noise.
