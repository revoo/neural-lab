## The problem: many vectors, many layers

In <LessonLink to="matrices">the matrices lesson</LessonLink>, one matrix transformed one vector. Real systems immediately want two things more.

First, **batches**. Nobody trains a network one email at a time. You push 32, or 512, or 4,096 examples through together, because hardware is vastly more efficient that way. That means applying the same matrix to a whole stack of vectors at once.

Second, **chains**. A neural network is a sequence of layers, each with its own matrix. The output of one becomes the input of the next. What does "apply matrix B, then matrix A" amount to?

Both questions have the same answer: **matrix multiplication**. And it brings along a companion skill that will save you more debugging hours than almost anything else in this course: reasoning about **shapes**.

<MachineMap highlight="stack" />

**Where this is going.** A network is layers in a pipeline: the output of one matrix becomes the input of the next. Multiplying matrices is how you compose those stages, and the shape rules here are the ones that crash or run your model code.

## Every row meets every column

You already know how to multiply a matrix by a vector: dot each row of the matrix with the vector. Now replace the single vector with a whole matrix of them, arranged as columns. Do the same thing for each column, and line the results up side by side. That's matrix multiplication.

<Analogy title="Think of a speed-dating evening">

The rows of $A$ sit along one side of the room. The columns of $B$ sit along the other. Every row has exactly one short conversation with every column, and the organiser writes down how well they got on — their dot product — in a big score sheet. That score sheet is $C = AB$. The entry in row $i$, column $j$ records the conversation between row $i$ of $A$ and column $j$ of $B$.

There's one rule for the evening: everyone must speak the same language. A row of $A$ can only have a conversation with a column of $B$ if they have the same number of entries. That single rule is the source of nearly every shape error you'll ever see.

</Analogy>

### The rule, in symbols

Here is the speed-dating rule in symbols. It's the most compact description of a huge amount of computation, so it's worth decoding slowly:

<Eq
  words="\text{score for (row } i\text{, column } j\text{)} = \text{add up, walking along both, } (\text{row } i \text{ of } A\text{'s entry}) \times (\text{column } j \text{ of } B\text{'s entry})"
  tex="\cc{C_{ij}} = \sum_{k=1}^{K} \ca{A_{ik}}\, \cb{B_{kj}}"
>

- $\cc{C_{ij}}$ — the **result** in row $i$, column $j$. Two subscripts, row first.
- $\ca{A_{ik}}$ — **row $i$ of $A$**, at position $k$ along it
- $\cb{B_{kj}}$ — **column $j$ of $B$**, at position $k$ down it
- $\sum_{k=1}^{K}$ — the inner loop: $k$ walks along the row and down the column together. $K$ is the **shared, inner dimension**.

</Eq>

<Predict
  question="A batch of shape $(32, 784)$ is multiplied by a weight matrix of shape $(784, 128)$. What shape comes out?"
  options={["(32, 128)", "(784, 784)", "(32, 784)"]}
  answer={0}
>

The inner 784s match and disappear; the outer sizes remain: 32 inputs, each now 128 numbers.

</Predict>

Notice where $k$ appears: as the *second* index of $A$ and the *first* index of $B$. It's summed over, so it vanishes from the result. The surviving indices, $i$ and $j$, tell you the output shape. That leads to the shape rule:

$$
(n \times \underbrace{K) \;@\; (K}_{\text{must match}} \times m) \;\to\; (n \times m)
$$

The inner dimensions must agree, and they get consumed. The outer dimensions survive.

## Matrix multiplication is composition

Here's the deeper meaning. Applying $B$ to a vector and then applying $A$ to the result gives exactly the same answer as applying the single matrix $AB$:

$$
A(B\mathbf{x}) = (AB)\mathbf{x}
$$

So **the product of two matrices is the transformation "do one, then the other"**, packed into a single matrix. One quirk of notation: because the matrix closest to $\mathbf{x}$ acts first, a product like $AB$ is read *right to left* — $B$ happens first. (If that feels backwards, think of nested function calls: in `f(g(x))`, `g` runs first.)

And because "do one, then the other" depends on the order — putting on socks then shoes is not the same as shoes then socks — matrix multiplication is generally **not commutative**: $AB \ne BA$.

<Deeper title="Why chaining linear layers is (almost) pointless" tag="Foreshadowing">

If each layer of a network just multiplied by a matrix, then a three-layer network would compute $C(B(A\mathbf{x})) = (CBA)\mathbf{x}$. And $CBA$ is just one matrix. Three layers, a hundred layers — it all collapses into a single matrix that could have done the same job alone.

That's a genuinely important result, and a slightly alarming one. It means depth is useless unless something *between* the matrix multiplications breaks the collapse. That "something" is the activation function, and it's the subject of <LessonLink to="activation-functions">its own lesson</LessonLink>.

</Deeper>

## Tensors: just arrays with more dimensions

You'll hear the word **<Term id="tensor">tensor</Term>** constantly. In physics it has a rich, subtle meaning. In machine learning code it means something refreshingly simple: **an n-dimensional array of numbers**.

| Rank | Name | Example shape | What it might hold |
| --- | --- | --- | --- |
| 0 | scalar | `()` | a single loss value |
| 1 | vector | `(768,)` | one token's embedding |
| 2 | matrix | `(32, 768)` | a batch of 32 embeddings |
| 3 | 3-D tensor | `(32, 512, 768)` | 32 sentences × 512 tokens × 768 features |
| 4 | 4-D tensor | `(32, 3, 224, 224)` | 32 colour images: channels × height × width |

The **<Term id="shape">shape</Term>** is the list of sizes, one per dimension. Learn to read shapes fluently and architecture diagrams turn into something closer to type signatures. Most of the "why doesn't this run?" errors in machine learning are shape errors, and most of the "why is this so slow / so big?" questions are answered by multiplying shapes together.

### Batched matrix multiplication

When a tensor has more than two dimensions, libraries treat matrix multiplication as acting on the **last two** dimensions, and every dimension before that as a batch of independent products. A `(8, 512, 768)` tensor times a `(768, 3072)` matrix means: for each of the 8 sequences, do a `(512 × 768) @ (768 × 3072)` product. Result: `(8, 512, 3072)`.

### Broadcasting

Element-wise operations like `+` need matching shapes — except that libraries quietly stretch dimensions of size 1, or missing dimensions, to fit. This is **<Term id="broadcasting">broadcasting</Term>**, and its rule is short: *line the shapes up from the right; each pair of sizes must be equal, or one of them must be 1.*

The most common use is adding a bias: a `(128,)` vector added to a `(32, 128)` batch gets repeated for each of the 32 rows. The most common bug is the same thing going subtly wrong, because broadcasting will happily produce a result of the "wrong" shape without any error at all.

## In code

Here's matrix multiplication three ways — the triple loop you watched above, the version that treats each output entry as a dot product, and the one you'd actually use:

```python
import numpy as np

def matmul_loops(A, B):
    n, K = A.shape
    K2, m = B.shape
    assert K == K2, f"inner dimensions differ: {K} vs {K2}"
    C = np.zeros((n, m))
    for i in range(n):
        for j in range(m):
            for k in range(K):
                C[i, j] += A[i, k] * B[k, j]
    return C

def matmul_dots(A, B):
    # every row of A meets every column of B
    return np.array([[row @ col for col in B.T] for row in A])

A = np.random.randn(64, 300)
B = np.random.randn(300, 50)
C = A @ B                          # what you'd really write: shape (64, 50)
np.allclose(C, matmul_loops(A, B)) # True — same numbers, ~1000× slower

# A linear layer applied to a batch, with a broadcast bias:
X = np.random.randn(32, 784)       # 32 examples
W = np.random.randn(784, 128)
b = np.random.randn(128)
H = X @ W + b                      # (32, 784) @ (784, 128) + (128,) → (32, 128)
```

One convention to watch for: in the maths we wrote a layer as $W\mathbf{x}$ with $\mathbf{x}$ as a column. In code, batches are usually stored with **one example per row**, so the same layer appears as `X @ W` with `W` transposed relative to the maths. PyTorch's `nn.Linear` stores its weight as `(out_features, in_features)` and computes `X @ W.T + b`. Same arithmetic, different bookkeeping — and a classic source of confusion when reading papers alongside code.

<Deeper title="Why GPUs love this operation" tag="Hardware">

Look at the triple loop again. Every one of the $n \times m$ output entries is independent of all the others, so they can all be computed *at the same time*. And each needs the same kind of simple multiply-add, over and over.

That's the ideal workload for a GPU, which is essentially thousands of small arithmetic units built to run the same instruction on different data in parallel. Modern GPUs go further with **tensor cores** — circuits that multiply whole small matrix tiles (e.g. 16×16 blocks) in a single step.

The cost is easy to estimate from shapes: an $(n \times K) @ (K \times m)$ product needs $n \cdot K \cdot m$ multiply-adds. For the transformer projection preset in the shape lab, that's $8 \times 512 \times 768 \times 3072 \approx 9.7$ billion — for one layer, on one batch. We'll come back to these numbers when we study inference and hardware.

</Deeper>

<Takeaways>

- Matrix multiplication: **every row of the left meets every column of the right**, and each meeting is a dot product. $C_{ij} = \sum_k A_{ik}B_{kj}$.
- Shape rule: $(n \times K) @ (K \times m) \to (n \times m)$. The inner dimensions must match and disappear.
- $AB$ means "apply $B$, then $A$". Order matters: $AB \ne BA$ in general.
- A tensor is just an n-dimensional array. In libraries, `@` acts on the last two dimensions and treats the rest as a batch.
- Broadcasting stretches size-1 or missing dimensions, aligning shapes from the right. It's convenient — and it can hide bugs.

</Takeaways>

<InTheWild>

If you profile a large language model, you'll find that the overwhelming majority of its arithmetic is matrix multiplication: projecting tokens into queries, keys and values; computing attention scores; and pushing every token through big feed-forward layers. Training a frontier model involves on the order of $10^{24}$ or more multiply-adds — and nearly all of them come from the humble triple loop you just watched, run in parallel on a scale that's hard to picture.

</InTheWild>
