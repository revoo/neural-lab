# CNNs and Feature Maps

In <LessonLink to="convolution">the convolution lesson</LessonLink>, a single `3×3` kernel could spot a vertical edge or a tiny cross. Real images are far richer than edges: a photograph of a bicycle contains spokes, tyres, handlebars, pedals, and a rider — shapes spanning dozens or hundreds of pixels.

How does a **<Term id="cnn">Convolutional Neural Network (CNN)</Term>** go from tiny `3×3` local dot products to recognising a whole bicycle anywhere in a high-resolution photo?

By stacking three simple ingredients over and over:

1. **Multi-channel convolutions** that compose earlier feature maps into richer patterns (edges → corners → textures → parts → objects).
2. **Nonlinearity (`ReLU`)** between layers so two stacked layers don’t collapse into one linear filter.
3. **<Term id="pooling">Pooling</Term> (or strided convolutions)** to shrink spatial maps, rapidly grow each neuron’s field of view, and trade exact pixel coordinates for shift invariance.

---

## 1. Receptive fields: how `3×3` sees the whole scene

A single `3×3` kernel looks at a tiny `3×3` patch of pixels. Now stack a second `3×3` kernel on top of the first feature map: each of its `9` inputs *already* summarised a `3×3` patch of the image, so one neuron in Layer 2 sees a **`5×5`** patch of the original image!

Now drop a `2×2` stride-2 pooling layer in between. Because adjacent cells in the pooled map are now **2 input pixels apart**, the **jump** (effective stride $j$) doubles from `1` to `2`. The very next `3×3` conv jumps across 2 input pixels per step, widening its **<Term id="receptive-field">receptive field</Term>** twice as fast!

<Eq
  words="new receptive field  =  old receptive field  +  (kernel − 1) × current jump"
  tex="\ca{r_\ell} = \ca{r_{\ell-1}} + (\cb{k_\ell} - 1)\,\cc{j_{\ell-1}}, \qquad \cc{j_\ell} = \cc{j_{\ell-1}} \cdot \cg{s_\ell}"
>
  - $\ca{r_\ell}$ — **receptive field** width after layer $\ell$ (starting from $r_0 = 1$)
  - $\cc{j_\ell}$ — **jump** (effective stride in input pixels between adjacent neurons; starting from $j_0 = 1$)
  - $\cb{k_\ell}, \cg{s_\ell}$ — kernel size and stride of layer $\ell$
</Eq>

## 2. Pooling: trading pixel coordinates for shift invariance

Remember from <LessonLink to="convolution">the convolution lesson</LessonLink> that convolution is translation **equivariant**: nudge an edge 1 pixel to the right, and the feature map nudges 1 pixel to the right.

Add **`2×2` Max Pooling** (stride 2): each `2×2` block simply reports its single strongest activation. If an edge jitters by 1 pixel inside its `2×2` block, the pooled output does not budge by a single decimal place!

<PoolingWidget />

At the very end of a modern CNN (ResNet, ConvNeXt, MobileNet), **<Term id="global-average-pooling">Global Average Pooling (GAP)</Term>** takes that idea all the way: average each of the $C$ channels across the entire remaining spatial grid `(H, W)`, turning `(7, 7, 512)` into a single `512`-number vector before the final linear classifier. That cuts VGG-16’s **106.9 million**-parameter dense head down to just **0.513 million** parameters (**208× smaller!**) while making the classifier completely blind to where in the photo the object appeared.

<ForReal>

In production `torchvision` vision backbones (ResNet, EfficientNet, MobileNetV2, ConvNeXt), almost every classifier ends with `nn.AdaptiveAvgPool2d(1)` followed by a single `nn.Linear(C, num_classes)`. That one swap — introduced in Network in Network (2013) and popularised by ResNet (2015) — eliminated the `4096→4096→1000` fully connected layers that accounted for the vast majority of VGG-16's parameters, while letting the same trained weights run on arbitrary input resolutions without reshaping a fixed dense matrix.

</ForReal>

## 5. Seeing receptive-field growth in 15 lines of Python

```python
def receptive_field(layers):
    r, j = 1, 1
    out = []
    for name, k, s in layers:
        r = r + (k - 1) * j
        j = j * s
        out.append((name, r, j))
    return out

stack = [
    ("Conv 3x3 s1", 3, 1),
    ("Conv 3x3 s1", 3, 1),
    ("MaxPool 2x2", 2, 2),
    ("Conv 3x3 s1", 3, 1),
    ("MaxPool 2x2", 2, 2),
    ("Conv 3x3 s1", 3, 1),
]
for name, r, j in receptive_field(stack):
    print(f"{name:12s} -> RF = {r:2d}x{r:<2d}  jump = {j}")
# Conv 3x3 s1  -> RF =  3x3   jump = 1
# Conv 3x3 s1  -> RF =  5x5   jump = 1
# MaxPool 2x2  -> RF =  6x6   jump = 2
# Conv 3x3 s1  -> RF = 10x10  jump = 2
# MaxPool 2x2  -> RF = 12x12  jump = 4
# Conv 3x3 s1  -> RF = 20x20  jump = 4
```
